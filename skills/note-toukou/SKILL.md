# note-toukou — noteに下書きを入れる

`~/note-kit/note-draft` のツールで、記事フォルダを note.com の下書きにする工程。

**公開は絶対にしない。** このツールは下書き保存で止まる作りになっている。公開ボタンはユーザーが自分で押す。

## 前提

- 入稿するものが `articles/<記事フォルダ>/` に揃っていること（`<記事フォルダ>` は note-auto の工程3-2で決めた名前）
  - `article.md`（frontmatter に `title` と `tags`。見出し画像があるときだけ `thumbnail`）
  - `images/` の中の画像（`.png` `.jpg` `.jpeg` `.webp`。本文中に `![説明](./images/xxx.png)` の形で参照されている）
- note.com にログイン済みであること（`storage/note-auth.json` がある）

## 手順

### 1. 環境を確認する

```bash
cd ~/note-kit/note-draft
npm run doctor
```

「✓ 保存済みログイン状態」の行が出ればOK。出なければ**ここで止まってユーザーに頼む**。

```bash
cd ~/note-kit/note-draft && npm run login
```

> **ID・パスワードは代わりに入力しない。** ブラウザが開くので、ユーザー自身がログインする。
> このコマンドは本人のログインを最大10分待つので、裏で動かして（バックグラウンド実行）終わりの知らせを待つ。

### 2. 入稿せずに下見する（dry-run）

```bash
cd ~/note-kit/note-draft
npm run dry-run -- articles/<記事フォルダ>
```

noteには一切アクセスしない。タイトル・文字数・画像枚数・タグが想定どおりか確認する。

### 3. 下書きを作る

```bash
cd ~/note-kit/note-draft
npm run draft -- articles/<記事フォルダ> --headed
```

`--headed` でブラウザを表示する。所要時間は**3〜5分ほど（画像が多いと10分近く）**。命令の待ち時間は既定で2分、最大でも10分で、画像が多いと超えることがある。**裏で動かして（バックグラウンド実行）**、終わりの知らせを待つ（打ち切られてやり直すと、下書きが2件に増える）。始める前に「3〜5分ほどかかります。ブラウザが勝手に動きますが、触らずにお待ちください」と伝える。

外部への書き込みなので、**ユーザーの指示がない限り勝手に実行しない**。本人が「入稿して」と言ったとき（または note-auto の工程7でOKが出たとき）に、**あなた（AI）が実行する**。本人にコマンドを打たせない。

### 4. 中身を検証する（ここを飛ばさない）

コマンドが成功しても、中身が正しいとは限らない。**必ず次の3つを見る。**

**1. 実行時の出力を見る**（いちばん早い）

`draft` の実行の最後に、次の形で数が出る。

```
本文画像: 7枚 挿入（本文の位置に置けず末尾に回した画像: 0枚）
リンクカード: 1個
リンクカードにならなかったURL（文字のリンクのまま入っています）: https://…
リンク付き画像: 1枚にリンクを付けました
```

- 「本文画像」の枚数が、`article.md` の中の `![…](./images/…)` の数と合っているか
- 「末尾に回した画像」が**0以外なら要調査**（位置に置けなかった画像が、記事の最後にまとめて入っている）
- 「リンクカードにならなかったURL」が出たら、そのURLはカードにならず、文字のリンクのまま入っている。カードにしたいときは、下書き画面でそのURLの行を消して貼り直してもらう
- 「リンク付き画像」の枚数が、`article.md` の中の `[![…](./images/…)](URL)` の数と合っているか。「リンクを付けられなかった画像」が出たら、その画像は入っているがリンクが無い。下書き画面で画像を選び、画像の上に出る鎖の印からURLを入れて「適用」を押してもらう

**同じ数が、ログファイル `logs/note-auto-draft.log` の `draft:done` の行にも残る。** ファイル名は日付つきではなく1本で、実行のたびに下に追記される。あとから見たいときは、最後の `draft:done` の行を読む。

- `imagesInserted` … 本文に入った画像の枚数
- `imagesLeftOver` … 位置に置けず末尾に回った枚数（0が正常）
- `linkCards` … リンクカードになった数
- `linkCardsFailed` … リンクカードにならなかったURLの一覧（空 `[]` が正常）
- `imageLinksSet` … リンクを付けた画像の数（リンク付き画像が無い記事では出ない）
- `imageLinksFailed` … リンクを付けられなかった画像のファイルの一覧（空 `[]` が正常）
- 実行時の表示に `body-image-insert-failed`（挿入に失敗した画像）・`images-appended-at-end`（末尾送りが起きた）・`image-link-failed`（画像にリンクを付けられなかった）の警告が出ていないかも見る（警告は画面の表示にだけ出て、ログファイルには残らない）

```bash
cd ~/note-kit/note-draft
grep "draft:done" logs/note-auto-draft.log | tail -1
```

> この書き方は Mac・Git Bash 向け。Windowsで命令がPowerShellで動いているときは
> `Select-String "draft:done" logs\note-auto-draft.log | Select-Object -Last 1` で読む（`tail` の代わりは `Get-Content logs\note-auto-draft.log -Tail 40`）。

**2. 入った中身をテキストで確認する**（ここを飛ばさない）

下書きURLを渡すと、本文の並びを1行ずつ、ブロックの種類の印つきで出してくれる。表・箇条書き・画像位置の確認はこれが一番速い。

```bash
cd ~/note-kit/note-draft
node scripts/verify-full.mjs "<下書きURL>"
```

出力の見方：

- 本文が上から1行ずつ並ぶ。ブロックの種類によって、行の頭に印が付く
  - `[見出し]` … 大見出し・小見出し
  - `[画像]` … 画像
  - `[画像→リンク] URL` … リンクの付いた画像（押すとそのURLが開く）
  - `[リンクカード] URL` … リンクカードになったURL
  - `[番号リスト N項目]` … 番号つきのリスト（N はその中の項目数）
  - `[箇条書き N項目]` … 箇条書き
  - `[コード]` … コードブロック
  - 印のない行 … ふつうの段落
- 最後に「== まとめ ==」として、見出し・画像・画像のリンク・リンクカード・箇条書き・番号リスト・番号リストの項目・文中のリンク・コードの数が出る
- 記事の上から下まで、1画面ずつの画面写しが `screenshots/verify-full-<日時>/` に `01.png` `02.png` … の順で保存される（最後の行に、保存した場所と枚数が出る）

見るところ：

- 画像が**本文の該当位置**にあるか（`[画像]` の行が、記事どおりの見出しの後ろにあるか。最後に固まっていないか）
- **見出しの数字が番号リストに化けていないか**（「1. 〜」で始まる見出しの行が `[番号リスト …]` ではなく `[見出し]` になっているか）
- **番号リストの項目数が記事と合っているか**（`[番号リスト N項目]` の N が、`article.md` のその番号リストの項目数と同じか。途中で1に戻って2つに割れていないか）
- **リンクカードの数が、記事の「URLだけの行」の数と合っているか**（まとめの「リンクカード」の数）
- **画像のリンクの数が、記事のリンク付き画像の数と合っているか**（まとめの「画像のリンク」の数。`[画像→リンク]` の行のURLが記事どおりか）
- 表が「**項目**：説明」の箇条書きになっているか（`|` が残っていないか）
- `**` や `` ` `` がそのまま文字として出ていないか

そのうえで、`screenshots/verify-full-<日時>/` の画面写しを `01.png` から順に Read で開き、**最後の1枚まで目でも見る**（画像の中身・太字・引用の見た目は、テキストでは分からない）。となり合う2枚は、ブロック1つぶん重ねて撮ってある。

**3. 画面を目で見る**

```bash
cd ~/note-kit/note-draft
node scripts/verify-draft.mjs "<下書きURL>"
```

`screenshots/verify-top.png` に記事の上部が保存されるので Read で開く。
サムネイル・タイトル・見出し・太字・引用がそろっているかを見る。

> `draft` 実行時にも `screenshots/` にスクショが残るが、**画面に見えている範囲だけ**（1280×720）。
> 記事の下のほうを見たいときは、上の `verify-full.mjs` のテキストと `screenshots/verify-full-<日時>/` の画面写しで確認する。

### 5. 報告する

- 下書きURL
- 画像が正しい位置に入ったか（枚数つき）
- 公開していないこと
- **タグの候補**（`article.md` の `tags:` に書いてあるものを、そのまま画面に並べる）。noteは自動でタグを入れられないので、**下書き画面で貼ってもらう**
- 残っている手作業があれば明記する

## 記法の対応状況（2026-08-06に全部通した）

| 記法 | 結果 |
|---|---|
| 大見出し・小見出し（`##` / `###`） | そのまま変換される |
| 箇条書き・番号リスト | 変換される。リストから段落に戻るのも正常 |
| 番号の行のすぐ下（空行なし）に書いた説明 | 同じ項目の中の改行として入り、番号が続く |
| 番号のあいだに空行つきの段落をはさむ | **番号が1からやり直しになる。** noteは番号リストの始まりの番号を保存しないため（「2.」から始めても保存すると1に戻る）。下見で注意が出るので、説明を番号の行のすぐ下に空行なしで書き直す |
| 引用（`>`） | 引用ブロックになる |
| 太字（`**`） | 行の途中も**行末も**変換される |
| コードブロック（``` の囲み） | 中身入りのコードブロックになる |
| インラインコード（`` ` ``） | **noteに変換規則が無い。** バッククォートを外してプレーン表示にしている |
| 表（`\| 項目 \| 説明 \|`） | **noteに表の機能が無い。** 箇条書き「**項目**：説明」に変換して入れる。ヘッダ行と区切り行は落とす。3列以上は2列目以降を「 / 」でつなぐ |
| 区切り線（`---`） | **落とされる。** `articleParser.ts` が「noteに無いので落とす」実装。noteでは見出しで章が分かれるので、記事としては問題ない |
| 画像 | 本文の該当位置に入る |
| リンク付き画像（`[![alt](画像)](URL)`） | 画像が入り、本文を入れ終えたあとでツールが画像にリンクを付ける（押すとURLが開く。2026-10-23に実機で確認）。画像だけの行に書く。URLは `https://` か `http://` で始める。付けられなかったときは画像だけ入り、実行時の表示に「リンクを付けられなかった画像」と出る |
| `__` を含む語の太字（`**@sample__name**`） | **使えない。** noteが `__` を強調記法と解釈してアンダースコアが消え、閉じの `**` だけ残る（`@samplename**` になる）。太字にせずそのまま書く |
| `_` を1つ含む語の太字（`**01_最初にこれを開く.html**`） | **使えない（2026-10-06に実機で確認）。** 太字に変換されず、`**` が前後とも文字のまま残る。ファイル名などは太字にせず「かぎかっこ」で囲む |
| URLだけの行 | noteがリンクカードに変換する。ツールは変換が終わるまで待ってから次を打つ。カードにならなかったURL（相手のサイトがページ情報を返さないとき）は文字のリンクのまま入り、実行時の表示の「リンクカードにならなかったURL」とログの `linkCardsFailed` に出る。カードにしたくないときは文章と同じ行にURLを置く |
| 文章の行末で終わるURL | リンクになる。そのままだとnoteがリンクにしないので、ツールがURLのあとに半角スペースを1つ足している |

インラインコードだけは見た目が普通の文字になる。強調したい語は太字か「かぎかっこ」にしておくと意図どおりになる。

## ツールが壊れたときの直し方

noteは画面デザインを変えるので、ときどき動かなくなる。慌てて何度も実行しない。

| 症状 | 見るファイル |
|---|---|
| タイトル欄・本文欄・下書き保存ボタンが見つからない | `src/selectors.ts` |
| 本文の見出し・箇条書きが崩れる | `src/noteEditorAdapter.ts` の `fillBody` |
| 画像の位置がおかしい | `src/noteEditorAdapter.ts` の `fillBody` と `insertImageAtCursor` |
| サムネイルが入らない | `src/noteEditorAdapter.ts` の `setThumbnail` |

直したら**必ず**この順で確認する。

```bash
cd ~/note-kit/note-draft && npm run typecheck && npm test
```

### noteエディタの実測ルール（直すときの前提）

ここを外すと崩れる。全部ハマった箇所。

- 段落の中で Enter を1回押すと**改行になるだけで、ブロックは変わらない**
- 新しいブロックにするには、段落やリストからは Enter 2回、見出しの直後と画像の直後は1回
- 見出し（`##`）・箇条書き（`- `）・コードブロック（```）は、**本当の空ブロックの先頭**で打ったときだけ変換される
- 太字などのインライン記法は、**閉じ記号の次の文字を打った瞬間**に変換される。閉じ記号が行末だと変換されないので、末尾に半角スペースを1つ打って変換させる
- コードブロックの**中では** Enter 1回がブロック内の改行、2回で外へ抜ける
- なので、コードブロックの中に**空行をそのまま置けない**。空行はEnterが2回続いた形になり、そこで抜けてしまう。空行では**半角スペースを1つ打って「文字のある行」にする**
- `page.keyboard.insertText('\n')` は**効かない**。noteのエディタが無視して全部1行につながる。改行はEnterで打つ
- 画像は「空のブロックに出る＋ボタン」から入れる。リストの中からは Enter 2回で抜けてから入れる
- URLだけの段落は、**Enterを押した瞬間に**リンクカードへの変換が始まる（打っただけでは変わらない）。変換中はその行が空になり、1〜3秒で、成功すればカード（`figure`）に、失敗すればURLの文字に戻る。変換の途中で次を打つと、カードにならず空の段落が残る。カードになったあとは、すでにカードの下の空のブロックにいる
- 行末で終わるURLはリンクにならない。URLのあとに文字（半角スペースでもよい）が来るとリンクになる
- 番号リストは、項目の中で **Shift+Enter** を押すと同じ項目の中の改行になる。始まりの番号は保存されない（`2. ` と打つと画面では2から始まるが、保存して開き直すと1に戻る）

### 2026-08-06に直したこと

**1. 画像が本文の位置を無視して末尾にまとめて入る**

`fillBody` が本文を打ちながら、`![](…)` の行に来たらその場で入れる方式に変更。パスで突き合わせるので順番がずれない。末尾にまとめる旧処理は保険として残し、**置けなかった分だけ**回る（ログの `imagesLeftOver` と `images-appended-at-end` で分かる）。

**2. コードブロックの中身が消えて黒い空箱になる**

``` を本当の空ブロックの先頭に置けていなかったのが原因。移動のEnter回数を直し、中身は Enter 1回区切りで打ち、最後に Enter 2回で抜けるようにした。

**3. 行末で終わる太字とインラインコードがそのまま出る**

`typeInline` を追加。行末が `**` なら半角スペースを1つ足して変換させ、インラインコードのバッククォートは外す。


### 2026-08-26に直したこと

**コードブロックに空行があると、そこで抜けて以降が普通の段落になる**

プロンプトを載せる記事で発覚。`case 'code'` が空行のとき文字を打たずEnterだけ押していたため、Enterが2回続いてブロックから抜けていた。空行では半角スペースを1つ打つように変更（`line.lines[i] || ' '`）。

先に `insertText('\n')` を試したが、こちらは**改行そのものが入らず全部1行につながる**ので使えない。改行はEnterで打つこと。


### 2026-08-30に直したこと

**URLだけの行の次のブロックが、まるごと消える**

noteはURLだけの行をリンクカードに変換する。その変換の途中で次のブロックへ移ると、ブロックごと消えて空段落だけが残っていた。
`case 'paragraph'` でURLだけの行を打ったあと2.5秒待つようにした。
→ **待つ場所が違っていた**ので、2026-10-03に直した（下を見る）。


### 2026-08-31に直したこと

**表がそのまま文字として入っていた**

`| 項目 | 説明 |` が変換されず、縦棒つきの本文としてnoteに入っていた（説明書は「箇条書きに変わる」と書いてあり、実装と食い違っていた）。
`articleParser.ts` に表の変換を実装し、上の表のとおり「**項目**：説明」の箇条書きになるようにした。

2026-09-01に**実機で入稿して確認済み**。noteの下書きに「**図解**：手順や比較を見せる」の形で入り、`|` は残らない。


### 2026-10-03に直したこと

**1. 番号の下に説明を続けると、番号が全部「1.」になる**

`1. **見出し**` のすぐ下に空行なしで説明を書くと、説明が段落として入ってリストが切れ、次の項目が「1.」からやり直しになっていた。
`articleParser.ts` で番号の行のすぐ下の行をその項目の続きとして持ち、`fillBody` で Shift+Enter（項目の中の改行）で打つようにした。
空行つきの段落をはさむ書き方は、noteが始まりの番号を保存しないため直せない。`articleValidator.ts` で下見のときに注意を出す。

**2. 最後のInstagramなどのリンクカードが、ときどき消える**

2.5秒待っていたのは「URLを打った直後」だったが、noteが変換を始めるのは**Enterを押した瞬間**だった。
そのため変換の途中（Instagramは1〜3秒かかる）に次の段落を打ち始めていて、カードにならず空の段落が残ることがあった。
Enterを押してから、カードになるか文字に戻るまで待つ（`waitForLinkCard`）ようにした。カードの下に余計な空行ができていたのも直った。

**3. 文章の行末で終わるURLがリンクにならない**

`友だち追加はこちらから https://…` のように行末で終わるURLが、ただの文字になっていた。`typeInline` で、行末がURLなら半角スペースを1つ足すようにした（太字の行末と同じ方法）。

3つとも実機で入稿して確認済み。


## やらないこと

- **公開しない。** 下書き保存で止める。公開はユーザーが画面で確認して手で行う
- **下書きを消さない。** 作り直しで不要になった下書きが出ても、削除はユーザーに頼む
- **同じコマンドを繰り返さない。** 失敗したら原因を特定して、次の手をユーザーに確認する
- **ログイン情報を入力しない。** ログインが切れていたらユーザーに頼む
