# note-auto — 発信noteを通しで1本作る

既存の職人スキル（note-outline / note-write / note-image / note-toukou）を順につないで、**1コマンドで下書き1本を仕上げる**司令塔。

**ジャンルは問わない。** 読者・文体・配色・誘導先・保存先は、`~/note-kit/note-themes/` のテーマ設定から読む。AI×副業でも、マイルでも、料理でも、手順は同じ。

- **止まるのは3か所だけ**：①構成を見せたあと（承認をもらう）②Notionへの保存（テーマ設定にnoteDBがある場合のみ）③note.comへの入稿
- **それ以外は確認を取らずに進む**：ネタ決め・本文・画像は、途中で聞かずに走る
- **入稿は、本人が「入稿して」と言ったら（または工程7で確認を取ったら）、あなた（AI）が note-toukou の手順で実行する**。本人にコマンドを打たせない
- **公開はしない**：noteの下書きまでで止める。公開ボタンは本人が自分で押す

> 各工程のルール本体はコピーせず、都度その職人スキルを読んで従うこと（二重管理しない）。

## 手順

### 0. テーマを決める（最初にやる）

`~/note-kit/note-themes/README.md` を読み、どのテーマで書くかを確定する。

1. ユーザーが指定していればそれを使う（「マイルのnote書いて」「料理のテーマで」など）
2. 指定がなく、頼まれた内容から明らかならそれを使う
3. どちらでもなければ**ここで止まって聞く**。勝手に既定を使わない

> **名前（`label`）や冒頭に「記入例」と付いたテーマ（同梱の `ai-fukugyo.md` `mile.md` `ryori.md`）は、本人のテーマとして使わない。**
> 書き方の見本で、中の失敗談や実績は本人のものではない。本人のテーマが1枚も無ければ、ここで止まり、`_template.md` をコピーしてテーマ設定を作る（`~/note-kit/CLAUDE.md` の「6. テーマ設定を作る（15の質問：必須7・任意8）」の手順）。

決まったらそのテーマファイルを最後まで読む。**`（要記入）`・`（例：`・`（例 ` の3つを探し、残っている項目があれば、そこで止めて項目名を伝え、ユーザーに埋めてもらう**（特にCTAと保存先。それ以外の項目で「このままでいい」と言われたら、そのまま進めてよい）。

以降の工程は、すべてこのテーマの内容に従う。

### 1. ネタを決める

ユーザーが記事のネタを言っていれば**それを使う**（この工程は飛ばす）。

言っていなければ自分で1本選ぶ。

1. テーマ設定の**効いたネタ**（過去に反応がよかったもの）を見る。近い切り口があれば、そこから広げる。
2. テーマ設定に**ネタ元**があれば、直近で伸びている記事を引く（無ければこの手順は飛ばし、WebSearchでそのジャンルの需要を調べる）。

```sql
SELECT "タイトル", "スキ数", "取得タグ", "見出し構成"
FROM "<テーマ設定のネタ元>"
ORDER BY "スキ数" DESC LIMIT 40
```

3. すでに書いた記事と被らせない。**テーマ設定に noteDB があるときだけ**、そこから既存タイトルを引いて突合する。無ければ `~/note-kit/note-draft/articles/` の中の記事フォルダ名と `article.md` のタイトルを見て突合する。

```sql
SELECT "タイトル", "状態" FROM "<テーマ設定のnoteDB>"
ORDER BY createdTime DESC LIMIT 200
```

4. **テーマ設定の「読者」**に刺さり、**まだ書いていない**ものを1本決める。**「触れない話題」に当たるネタは選ばない。**
5. 画面に3行だけ出す：選んだネタ／狙い（読者の持ち帰り）／誘導先。**承認は求めず次へ進む**。

### 2. 構成を作る

`note-outline/SKILL.md` の「この記事の型」「設計の手順」「出力フォーマット」に従って構成を組む。

- 組んだ構成を画面に出し、**ここで一度だけ止まって承認をもらう**。最後にこう聞く。

  > この構成で本文を書いてよいですか？（直したい見出しがあれば教えてください）

- 直しの指示が来たら反映して、もう一度見せる。OKが出たら本文へ進む
- **ここを飛ばさない。** このあと本文と画像で20〜35分走るので、構成を直すなら今しかない
- タイトルは案を出したうえで**自分で1つ決める**（タイトルの承認までは求めない）

### 3. 本文を書く

`note-write/SKILL.md` の文体ルール・AI感を消す・事実の裏取り・コンプラ・**修正ループ（総合95点以上）**にすべて従う。

- 独自性と事実確認は毎回WebSearchで実照合する（検索せずに合格にしない）
- **この段階ではまだNotionに保存しない**
- 何度直しても95点に届かない、または事実の裏が取れないときは、無理に通さず理由を報告して止まる（迂回して別の手を試さない）
- **本文の先頭に、タイトルと同じ見出し（`# タイトル`）を書かない。** タイトルは `article.md` の frontmatter の `title:` で入るので、本文にも書くと二重になる

### 3-2. 記事フォルダを決めて作る（画像づくりの前にやる）

画像の保存先になるので、**画像を作る前に**記事フォルダを決めて作っておく。

- 記事フォルダ名は `<接頭辞><slug>`。接頭辞はテーマ設定の「記事フォルダの接頭辞」（例：`mile-`）。**接頭辞が無いテーマなら `<slug>` だけ**
- `<slug>` は英小文字とハイフン（例：`tokuten-koukuuken`）。`articles/` の中の既存フォルダと被らせない
- 以降、このスキルと note-image・note-toukou の `<記事フォルダ>` は、すべてこの名前を指す

```bash
cd ~/note-kit/note-draft
mkdir -p articles/<記事フォルダ>/images
```

### 4. 画像を作る（課金なし）

`note-image/SKILL.md` と `references/zukai-style.md` を読んでから作る。保存先は `~/note-kit/note-draft/articles/<記事フォルダ>/images/`（サムネイルだけは記事フォルダの直下に `thumbnail.png`）。

**ここは15〜20分かかる工程。黙って走らない。** note-image の「途中経過を伝える」に従い、
始める前に枚数と所要時間を1行で伝え、**1枚できるたびに `[3/7] …` の形で1行報告する**。

**先にテーマ設定の「画像の好み」→「Codexを入れたか」を見て、分かれる。**

- **入れた** → 図解と人物イラストは **Codexの `/imagegen`（Image 2.0）** で作る。OpenAIのAPIキー課金はかからない。**サムネイル（見出し画像）も1枚作る**
- **入れていない** → 図解は note-image の「**Codexなしで図解を作る（HTMLで作る）**」の手順で作る。**サムネイル（見出し画像）と人物イラストは作らない**（本人に用意してもらう旨を最後の報告で伝える）

共通のルール：

- **ワンスクロールに最低1枚**。目安は**500字に1枚**。3,500字なら7〜8枚（詳細は note-image の「何枚入れるか」）。**テーマ設定のCTA固定画像はこの枚数に数えない**（作るものではなく、既にある素材を貼るだけ）
- 本文のどの見出しの後ろに何を置くかは自分で決める（設計の確認は取らない）
- Codexの呼び出し方は、note-image の「**共通：Codexの呼び出し方**」に従う（`< /dev/null` と `echo` の印と `-s workspace-write` を必ず付け、待ち時間を最大にして実行する）
- **1回に1枚**。保存は「cp でコピーするだけ」と必ず書く（リサイズを頼むと止まる）
- できた画像は**必ずReadで目視**し、品質チェックリスト（日本語の崩れ・余計な文字・見切れ・色）を通す
- 失敗しても同じコマンドを繰り返さない。原因を確認して次の手をユーザーに聞く
- 1枚も作れなくても**本文は完成させる**。画像なしで先へ進み、その旨を最後に報告する

### 4-2. 操作画面のスクリーンショットを撮る（該当する記事だけ）

記事の中に「登録方法」「操作手順」など、**実際の画面を見せたほうが伝わる箇所**があれば撮る。

- 撮り方は `note-image/SKILL.md` の「3. 操作画面のスクリーンショットを撮る」に従う
- 画像と同じく、撮るたびに1行で報告する（枚数が多いときは相手が待つことになる）
- **ログインが必要な画面では、IDやパスワードを入力しない。** ログインが要るときはここで止まり、ユーザーにログインを頼む
- **パソコンのアプリ画面（Web以外）を撮るときは、撮る前に本人に聞く**（note-image のとおり。撮った画像はAIが開くので会話の相手に送られることも伝える）
- 撮ったら必ず目視し、メールアドレス・鍵・他人の名前・課金情報が写っていないか確認する。写っていたら貼らない
- 該当箇所がない記事では、この工程を飛ばす

### 5. 記事フォルダに書き出す

工程3-2で作った `articles/<記事フォルダ>/` に、`article.md` を書き出す。

**CTA固定画像をコピーする**（テーマ設定にその節があるときだけ）。テーマ設定の「CTA固定画像」の表の**ファイル列に書いてあるファイル名**を、素材の置き場所から記事の `images/` へ、頭に `cta-` を付けた名前でコピーする。ファイル名は決め打ちしない（表が `seminar.png` と `line.png` の2行なら、その2枚だけ）。

```bash
cd ~/note-kit/note-draft/articles/<記事フォルダ>
# 例：表のファイル列が seminar.png の場合
cp ~/note-kit/note-assets/<テーマ名>/seminar.png images/cta-seminar.png
```

素材が見つからないときは、そこで止めてユーザーに置き場所を聞く（勝手に別の画像で代用しない）。

`article.md` の形：

```markdown
---
title: 決定したタイトル
thumbnail: ./thumbnail.png
tags:
  - （テーマに合ったタグを3〜5個）
---

本文…（先頭に「# タイトル」は書かない。いきなりリードの文章から始める）

![図解の説明](./images/fig1-xxx.png)

## 見出し

続き…
```

- **`thumbnail: ./thumbnail.png` の行は、見出し画像ができたときだけ書く。** Codexを入れていない・作れなかったときは、この行ごと消す（ファイルが無いのに書くと、下見でエラーになって入稿が止まる）
- 画像は本文の該当見出しの直後に `![](./images/…)` で入れる
- **CTA固定画像は、テーマ設定の表どおりの位置**に `![alt](./images/cta-◯◯.png)` で入れる。表の「画像のリンク先」にURLがあるものは `[![alt](./images/cta-◯◯.png)](URL)` と書く（入稿のときに画像にリンクが付く）。画像を続けて並べず、あいだに文章を挟む。URLを置く指定があるものは画像の直後に置く（**URLだけの行にしない**。文章と同じ行に入れる）
- 対応形式は `.png` `.jpg` `.jpeg` `.webp` のみ
- 書き出したら**画像と画像の間隔を数える**。1,000字以上あいている箇所があれば画像を足す（CTA固定画像はこの数えに入れない）

### 6. Notionに下書き保存（**設定がある場合だけ**）

テーマ設定に「noteDB」の指定が無ければ、この工程は飛ばして工程7へ進む。Notionを使っていなくても、記事フォルダとnoteの下書きだけで完結する。

指定がある場合は、書き込む前に一度だけ聞く。

> noteDBに下書きとして保存してよいですか？

OKが出たら `notion-create-pages` で**テーマ設定のnoteDB**に1件作る。

- タイトル＝決定タイトル／状態＝下書き／日付＝当日
- 本文は Notion Markdown（`##` `###`・太字・箇条書き）で構成を反映する

### 7. noteに下書きを入れる（**ここも止まる**）

工程6が終わったら（飛ばした場合はそのまま）、続けて聞く。

> noteにも下書きを入れますか？

OKが出たら、あなた（AI）が **note-toukou スキル**に従って入稿する（下見 → 入稿 → ログとスクショで検証まで）。公開はしない。
断られたら飛ばす。あとで本人が「入稿して」と言ったら、そのとき note-toukou の手順で実行する。

### 8. 報告する

日本語で簡潔に。絵文字は使わない。

- Notionページのリンク（保存した場合）
- 実際の文字数と最終スコア
- 作った図解の枚数
- **記事に付けるタグの候補（3〜5個）**。noteは自動でタグを入れられないので、**候補をそのまま画面に並べて**、下書き画面で貼ってもらう
- 記事フォルダのパス（`~/note-kit/note-draft/articles/<記事フォルダ>`）
- 入稿した場合は、note-toukou の「5. 報告する」の中身（下書きURL・画像が正しい位置に入ったか など）
- 入稿していない場合は、「noteの下書きに入れたくなったら『入稿して』と言ってください。私が入れます（公開はしません）」と一言添える。**本人にコマンドを打たせない**
- 見出し画像を作らなかった場合は、その旨と「見出し画像はnoteの下書き画面でご自身の画像を設定してください」と添える

## 注意

- 止まるのは**工程2の構成の承認**と、外に出す直前（**Notion書き込み**と**note入稿**）。Notionを使っていなければ、止まるのは構成と入稿の2回
- 例外は工程4-2。**スクショにログインが必要なとき**と、**パソコンのアプリ画面を撮るとき**だけ止まってユーザーに頼む（認証情報は絶対に代わりに入力しない）
- noteの**公開ボタンは押さない**。下書きまでで止め、公開はユーザーが手で行う
- 構成にない話を足して文字数を稼がない
- 見本記事の表現を写さない。型は真似ても言葉は独自にする
- クライアントから請け負うSEO記事には向かない（このスキルは自分の発信・集客note専用）
